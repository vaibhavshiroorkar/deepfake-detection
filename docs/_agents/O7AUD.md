### Whisper fixed 30 s window: exactly what it means for short clips

- `WhisperFeatureExtractor.__call__` has defaults `padding="max_length"`, `truncation=True`, and `max_length` = `n_samples` = 480,000 samples (30 s at 16 kHz) (feature_extraction_whisper.py, transformers v5.20.2). So a 4 s clip (64,000 samples) is zero-padded with 416,000 zero samples, a longer than 30 s clip is truncated, and the log-mel array is always 80 x 3000.
- Log-mel normalisation in the same file: `log_spec = np.maximum(log_spec, log_spec.max() - 8.0)` then `(log_spec + 4.0) / 4.0`; the maximum is taken over the whole padded window.
- `WhisperEncoder.forward` raises `ValueError` ("Whisper expects the mel input features to be of length 3000, but found ... Make sure to pad the input mel features to 3000") for any other length (modeling_whisper.py, v5.20.2). Its docstring says `attention_mask` "is preserved for compatibility, but it is not used" (the encoder has no padding mask).
- Consequence for features: the transformer processes all 1500 positions (the padded region included) for every clip, so the encoder cost is that of 30 s for a 4 s clip, and the valid frames attend to padded frames. The first 200 positions (4 s / 20 ms) hold the speech. If pooling is done over the 1500 output positions, 87 per cent of the pooled frames are padding for a 4 s clip, so any pooling must use a mask of valid positions (ceil(samples / 320) positions; the feature extractor can return an attention_mask rescaled to 3000 mel frames, see the `return_attention_mask` branch). Truncating `embed_positions` to fewer positions requires changing the library code and its effect on features was not verified (NR).

### Diversity of families (criterion 5), descriptive only
