## 2. Result contents and mapping to schema v2 (from general C2PA knowledge, field names not verified in this session)

A reader result normally holds: validation state or status codes, the active manifest, signer (certificate subject), claim generator, assertions (c2pa.actions, ingredients, hash bindings), and optionally an IPTC digitalSourceType such as trainedAlgorithmicMedia.

| Verifier outcome | provenance finding |
|---|---|
| Manifest found, signature and hash binding valid, signer trusted by configured list | credentials_valid |
| Manifest found, signature or hash binding fails, or signer untrusted/expired | credentials_invalid (record the failure codes) |
| No manifest after a real parse | no_credentials_found |
| Unsupported format, parse error, truncated scan, no trust list configured, network needed but disallowed | inconclusive |

What a valid manifest does NOT prove: it attests to signed claims about the asset at signing time. It does not prove every pixel or sample is authentic, nor that no edit happened outside the manifest chain. Absent, stripped or unsigned credentials prove nothing, and `no_credentials_found` must never be shown as evidence of fakeness or authenticity. A valid credential that declares AI-generated content (for example trainedAlgorithmicMedia) should be shown as "signed declaration: AI-generated by <signer>", a provenance fact, kept separate from our detector score and not blended into it.

## 3. Current local state and work required

`src/dfd/platform/provenance/metadata.py` only searches the bytes for `jumb` and `c2pa`; `c2pa_verifier_available()` checks `importlib.util.find_spec("c2pa")`, and `modules.py` therefore returns only `inconclusive` or `no_credentials_found`. c2pa is not installed.

To wire a verifier:
1. Approval to install (pip) and confirm a Windows wheel exists; else use Linux/WSL or c2patool.
2. Record package, version, hash and licence in `docs/DATA_LOG.md` (rule 7); record the trust list source and licence too.
3. Approval for any trust-list download; decide offline policy and set remote fetch/OCSP off.
4. Write the adapter that maps results per section 2; add tests with known signed and tampered sample files (sample files need provenance logging, no user media sent to external services).
5. Log a decision (DECISIONS) and update FILES, PLAN, STATUS.
